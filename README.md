# NnRepositoriyWiFy — Telegram-бот для роутера TP-Link Archer C80

Бот подключается к роутеру **TP-Link Archer C80** и позволяет смотреть его состояние
и менять настройки прямо из Telegram. Работает из домашней сети, наружу ничего не торчит —
бот сам ходит по роутеру через его веб-API (библиотека
[tplinkrouterc6u](https://github.com/AlexandrErohin/TP-Link-Archer-C6U), Archer C80 1.0/2.20 поддерживается).

## Возможности

| Команда | Что делает |
|---|---|
| `/status` | Модель, прошивка, WAN/LAN IP, шлюз, DNS, аптайм, состояние Wi-Fi сетей, число клиентов |
| `/wifi` | Настройки Wi-Fi: SSID, вкл/выкл 2.4 и 5 ГГц, гостевых сетей, показ паролей |
| `/setssid 2g\|5g\|g2g\|g5g <имя>` | Сменить имя Wi-Fi сети |
| `/setpass 2g\|5g\|g2g\|g5g <пароль>` | Сменить пароль Wi-Fi (сообщение с паролём бот удаляет из чата) |
| `/clients` | Карточка каждого устройства: трафик, время онлайн, сигнал; **блокировка**, **лимит скорости**, **закреп IP**, **WoL** — кнопками |
| `/stats` | Статистика трафика: топ устройств по объёму, текущие скорости, суммарный трафик |
| `/limit <mac/имя> <Мбит> [отдача]` | Лимит скорости устройству (напр. `/limit iphone 20 5`); `/limit iphone off` — снять |
| `/reservations` | Статические привязки MAC → IP, удаление кнопками |
| `/reserve <mac/имя> <ip> [имя]` | Закрепить IP за устройством |
| `/wol <mac/имя>` | Разбудить устройство (Wake-on-LAN) |
| `/task` | Задачи по расписанию: `/task add reboot 04:00`, `/task add wifi5_off 23:00 пт,сб` |
| `/logs` | Журнал роутера (последние 12/24 записи) |
| `/ports` | UPnP вкл/выкл + состояние DMZ |
| `/dmz <ip\|off>` | Включить DMZ на устройство / выключить |
| `/ddns` | DDNS-записи роутера, включение/выключение |
| `/reboot` | Перезагрузка роутера (с подтверждением) |
| `/help` | Главное меню |

В `/status` дополнительно показывается текущая скорость WAN (поля inRates/outRates блока 23).

Действия для `/task`: `reboot`, `wifi2_on/off`, `wifi5_on/off`, `guest2_on/off`, `guest5_on/off`.
Задачи хранятся в `tasks.json` и выполняет бот (время — локальное время машины, где он запущен;
у роутера своего cron нет). При выполнении каждой задачи бот присылает уведомление админам.

Управление дублируется инлайн-кнопками под сообщениями.

## Требования

- Python 3.10+ на машине **в той же сети, что и роутер** (ПК, ноутбук, Raspberry Pi, домашний сервер);
- роутер Archer C80 с известным **локальным паролем администратора** (тот, что вводится при входе
  на http://192.168.0.1; логин через TP-Link ID для API не работает);
- бот в Telegram (через [@BotFather](https://t.me/BotFather)).

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Создай бота у **@BotFather** → получи токен.
2. Скопируй `.env.example` в `.env` и заполни:

```bash
cp .env.example .env
```

| Переменная | Что вписать |
|---|---|
| `TG_BOT_TOKEN` | Токен от BotFather |
| `ROUTER_PASSWORD` | Локальный пароль администратора роутера |
| `ROUTER_HOST` | Адрес роутера, по умолчанию `http://192.168.0.1` |
| `ADMIN_IDS` | Твой Telegram ID (через запятую, если админов несколько) |

3. **Как узнать свой Telegram ID:** оставь `ADMIN_IDS=` пустым, запусти бота и напиши ему `/start` —
   он ответит с твоим ID. Впиши его в `.env` и перезапусти.

> ⚠️ `.env` в `.gitignore` — не коммить токен и пароли в репозиторий.

## Запуск

```bash
source .venv/bin/activate
python -m routerbot --check           # проверка конфига и связи с роутером
python -m routerbot --probe-blocks    # диагностика: скан блоков протокола роутера
python -m routerbot --probe-block 20  # полный дамп одного блока (без обрезки)
python -m routerbot                   # запуск бота
```

Карта блоков протокола Archer C80 v2.0 (по результатам `--probe-blocks`):

| Блок | Содержимое |
|---|---|
| 2 | системный лог (`/logs`) |
| 12 | статические DHCP-привязки (`/reservations`) |
| 13 | клиенты, блокировки, лимиты, трафик (`/clients`, `/stats`) |
| 17–19 | NAT ALG, **DMZ** (18), **UPnP** (19) → `/ports` |
| 20, 21 | Virtual Server = проброс портов (разметка уточняется) |
| 23 | WAN в реальном времени (скорость → `/status`) |
| 33 | настройки Wi-Fi сетей (`/wifi`) |
| 38, 39 | **DDNS** + статус (`/ddns`) |
| 59 | port triggering |
| 79 | состояние LAN-портов |

Температуры у C80 **нет** — железо её через прошивку не отдаёт вообще.

## Автозапуск (Linux/systemd, по желанию)

```ini
# /etc/systemd/system/routerbot.service
[Unit]
Description=Telegram bot for Archer C80
After=network-online.target

[Service]
WorkingDirectory=/opt/NnRepositoriyWiFy
ExecStart=/opt/NnRepositoriyWiFy/.venv/bin/python -m routerbot
Restart=always
RestartSec=10
User=routerbot

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now routerbot
```

## Важные нюансы

- **Одна сессия на роутере.** Archer C80 пускает только одного администратора одновременно.
  Бот на каждое действие заходит и сразу выходит, но если ты параллельно сидишь в веб-морде роутера —
  тебя может выкидывать, а запросы бота — мгновенно фейлиться. Это норма.
- **Пароль — локальный.** Не пароль Wi-Fi и не TP-Link ID, а пароль входа в веб-интерфейс.
- **Смена пароля Wi-Fi** отключит всех клиентов этой сети — им нужно будет ввести новый пароль.
- Работа смены SSID/пароля, блокировки устройств и лимитов скорости реализована через поля
  `cSsid` / `cPskSecret` / `blocked` / `upLimit` / `downLimit` протокола прошивки C80. Проверено на
  структуре ответов прошивок 1.0/2.20; если у тебя другая ревизия и что-то не сработает — пришли
  ответ роутера, поправим.
- Ограничение скорости: прошивка хранит лимиты в Kbps на устройство; заводские значения
  (1024 Мбит/с ⬇️ и 200 Мбит/с ⬆️) бот считает «без лимита». «Снять лимит» возвращает эти значения.
- Счётчики трафика (`/stats`) роутер ведёт с момента включения или сброса — после ребута они
  обнуляются.
- **Статический DHCP**: после `/reserve` устройство получит закреплённый IP при следующем
  переподключении. Удаление привязки прошивка делает «обнулением» записи — если после удаления
  остался мусор в веб-морде, скажи, поправим формат.
- **Wake-on-LAN**: пакет шлёт машина бота — она должна быть в той же сети; на целевом устройстве
  WoL должен быть включён (в BIOS/драйвере), надёжнее всего работает по кабелю.

## Если бот не достукивается до Telegram

Ошибка `ConnectionResetError` / `Cannot connect to host api.telegram.org` — это провайдер
(DPI) рвёт соединение с Bot API Telegram. Оно не лечится кодом, лечится путём трафика:

1. **Прокси** (для самого бота): допиши в `.env`
   ```ini
   TG_PROXY=http://хост:порт       # или socks5://хост:порт
   ```
   Бот пойдёт в Telegram через прокси (трафик к роутеру остаётся напрямую).
2. **VPN на машине**, где крутится бот.
3. **VPN на роутере** (PPTP/L2TP-клиент в веб-морде C80) — пустит через VPN вообще всю сеть.

При старте бот делает 5 попыток соединения с паузой — плавающие обрывы переживаются.
